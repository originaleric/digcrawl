# 2026-11-26 微信视频号登录转写与服务生命周期修复

微信视频号短链读取接入现有平台执行器，使用本人在腾讯元宝专用浏览器中的登录会话解析视频，复用受限 MP4 下载、转写、OCR 与 Collect 导出。此次修复整理于微信支线，并随微信能力合入 main。

## 登录与读取

`wechat.channels.read` 支持 `https://weixin.qq.com/sph/…` 普通视频短链。未登录时返回结构化 `LOGIN_REQUIRED` 和绑定当前 profile 的登录命令；用户在专用浏览器完成登录并保存会话后，重试原链接。主程序 `digcrawl` 可直接使用这一能力，无需另行安装专属微信版。宿主 Agent 根据返回的正文及 `asr_text` 生成摘要。

需要本机转写时，使用同一配置域执行 `asr setup` 与 `asr check`，准备 ffmpeg、Python 和模型。登录会话、runner 和模型缓存属于不同运行资源，应按实际配置分别核对。独立安装使用稳定的用户安装目录，避免依赖 Documents 工作区内的临时 runner 或虚拟环境。

## 下载和执行边界

对携带完整实体 Content-Range 的 HTTP 200 响应，核对完整区间、声明长度及 MP4 轨道样本范围后接收。截断、不完整分段、超限和无效 MP4 均返回失败并清理临时文件。测试使用合成媒体夹具，不提交真实视频或签名播放地址。

短链解析、可选截图、下载、ASR 与 OCR 使用既有执行预算，显式 deadline 优先。Provider 视频保留使用 `VideoDownload.Providers.wechat_channels`，Collect 继续遵循原有导出和媒体保存设置。

## 服务安装与重启

修复 macOS plutil 按数组索引 replace 导致 launcher 参数累积的问题，统一写入专用 launcher 与 `run-foreground` 两项。

重装时，以现有 plist 的 WorkingDirectory 为默认值，且与环境 DIGCRAWL_WORKDIR 一致写入。只有显式设置 DIGCRAWL_WORKDIR 才迁移工作目录。无法读取旧目录或目录不存在时，在构建、停服和替换服务定义前失败。微信 wrapper 保留默认值和显式覆盖的区别；构建继续在源码工作区执行。首次安装沿用现有目录规则，其他自定义安装参数仍需显式提供。

修复 macOS Bash 3.2 在未设置 build tags 时展开空数组的兼容问题。现有 `digcrawl-wechat` 独立 Gateway 服务入口保留兼容，合入 main 不会自动重装或迁移本机服务，也不会改变原有实例的监听地址、会话和配置。

## 验证与限制

2026-11-26 在 macOS arm64 完成删除元宝会话、未登录提示、人工登录保存及原链接重试。后续真实视频读取取得 451 字符本机转写；前一轮隔离验收已覆盖宿主摘要。专有名词识别准确度未人工校对。

本轮服务修复已通过系统 Bash 3.2 下的完整生命周期回归，分别使用真实 plutil 与模拟解析器，覆盖首次安装、显式迁移、重复重装、实际 launcher 目录、异常前置拒绝及原有失败恢复。main 用户级 ASR 和微信原、现配置的同音频对照均转写成功。项目目录内另一套 Python 环境复现依赖导入超时，并发现 dataless 文件；首次“无 JSON 转写”的触发原因仍未确定，不将资源调整描述为已证明修复该原始故障。
