# 2026-09-03 微信视频号下载兼容性与大小限制

## 范围

本次更新仅适用于本地 `local/wechat-channels-bridge` 分支中的 macOS 微信视频号实验能力，不进入 `main`，也不作为公开稳定下载能力发布。

## 本次变更

- `wechat-channels download` 与 `wechat-channels capture` 为单个视频加入统一的下载大小上限，默认 `2 GiB`，可用 `--max-bytes` 显式调整。
- 桥接会在已知 `Content-Length` 超限时拒绝下载；未知长度响应也会以流式上限检测。任何超限或超时都不会发布部分 MP4，并会清理临时文件。
- 下载协议能力写入桥接状态文件。新 CLI 在用户确认前检查该能力；若终端 A 仍是旧桥接，会明确提示停止并重新启动桥接，而不是返回难以判断的通用 HTTP 400。
- 为保证反向兼容，旧 CLI 连接到新桥接且未发送大小上限时，新桥接仍会应用同一 `2 GiB` 安全默认值；不会回退到无上限下载。
- `wechat.channels.read` 已纳入此分支的 Gateway、Collector 和 Skill 默认只读工具列表；严格域名白名单读取分享链接时需要允许 `weixin.qq.com` 与 `channels.weixin.qq.com`。
- 修复一键 `capture` 的自动输出和会话路径：它们在传给绝对路径受限的桥接下载接口前会解析为绝对路径。与此同时，桥接会原样保留已校验的 QQ 播放 URL 完整查询串，避免丢失签名参数而导致上游 HTTP 400；URL、token 与解密信息仍不会写盘、输出或返回给 CLI。

## 真实验收补充

- 已在用户授权的 macOS 微信桌面端会话中完成一次端到端下载：一键 `capture` 在桥接就绪后识别播放资源、成功生成默认自动命名 MP4，并在退出时清理本次会话目录；文件可由 `ffprobe` 解析，权限为 `0600`。完整脱敏证据见 `tests/2026-09-03/2026-09-03-第1轮-生产模拟测试报告.md`。
- `storage/digcrawl/wechat-channels-captures/` 是工作树内的默认归档根；CLI 会把其中自动生成的输出和会话路径解析为绝对路径后再传给桥接。
- `--yes` 仅跳过 CLI 确认，不能替代 macOS 钥匙串授权。一次一键任务可能在启动时因添加临时本地 CA、并在下载完成清理 CA 时各显示一次系统密码提示；用户只应在本机系统弹窗中处理密码，DigCrawl 不会读取、保存或请求该密码。

## 使用与恢复

终端 A 与终端 B 应使用同一次构建的当前二进制。若下载前提示“does not support bounded downloads”，先用同一状态目录停止旧桥接，再重新启动带 `--page-adapter` 的当前桥接：

```bash
./digcrawl wechat-channels bridge stop \
  --state-dir /tmp/digcrawl-wechat-channels-test

./digcrawl wechat-channels bridge start \
  --yes \
  --page-adapter \
  --state-dir /tmp/digcrawl-wechat-channels-test
```

不要手动编辑桥接状态文件或为了兼容旧桥接移除下载上限。

## 验证

- 覆盖旧桥接状态拒绝、新桥接状态声明和旧 CLI 缺省上限三条兼容路径。
- 覆盖声明长度与流式未知长度两种超限下载，确保不发布输出且不遗留临时文件。
- 已通过 `go test ./...`、`go vet ./...`、竞态检查与 CLI 构建。

完整操作步骤见[微信视频号本地抓取使用手册](../docs/微信视频号本地抓取使用手册.md)。
