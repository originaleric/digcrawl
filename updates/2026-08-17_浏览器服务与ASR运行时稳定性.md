# 2026-08-17 浏览器服务与 ASR 运行时稳定性

## 本次更新

- 将本地浏览器连接改为显式生命周期管理：活跃连接、退役连接、租约与启动中的连接互斥管理。浏览器异常后会先等待既有 profile 锁和固定 CDP 端口释放，再创建替代实例，避免旧进程与新进程争用同一登录 profile。
- 浏览器错误改为稳定的结构化代码、阶段、可重试标记和脱敏原因；MCP、HTTP 与 Collector 保持同一错误语义，便于定位 `页面关闭`、`CDP 不可用`、超时等问题。
- `ChromePath` 不再依赖写死的 Playwright 版本化缓存目录。未配置或已失效时，DigCrawl 会动态发现系统 Chrome/Chromium 与当前可用的 Playwright shell。
- 新增 macOS、Linux、Windows 的用户级 CDP 浏览器服务脚本；服务保留专用 profile、回环 CDP 端口和已验证的浏览器路径，并能识别端口被其他 profile 占用的情况。
- 本地 ASR 使用 profile 级持久缓存。旧 Skill profile 会兼容复用旧 `HF_HOME`、`HUGGINGFACE_HUB_CACHE` 或旧 cwd 缓存，并以原子状态文件记录选择结果；不会移动已有模型，也不会在服务重启后重新依赖 cwd。
- 内嵌 `faster-whisper` runner 改为内容版本化文件名，升级 DigCrawl 后会自动使用新版 runner；仓库中的独立脚本与内嵌资源由测试保持一致。
- 默认配置示例不再预设项目内虚拟环境或相对脚本路径。未设置本地 runner 时优先使用已安装的 `faster-whisper`，否则使用内嵌 runner 并依次尝试 `python3`、`python`、`py`。

## 行为与运维说明

- 视频正文读取的浏览器阶段使用共享 40 秒预算；显式媒体下载与 ASR 仍使用各自配置的顺序预算，不会被默认 MCP 60 秒时限提前取消。
- `skill.asr.enable` 在写入 opt-in 前会离线检查 ffmpeg、Python/faster-whisper 与已缓存模型。依赖缺失时返回结构化错误，配置不会被写成已启用状态。
- 使用 `CDPConnectExisting: true` 时，推荐通过 `scripts/digcrawl-cdp-browser-service.sh` 或 Windows PowerShell 脚本安装专用服务，而不是连接日常浏览器 profile。

## Windows CI 回归修复

- 修复 Windows CI 中测试夹具依赖 `#!/bin/sh` 的问题。此前 ASR、媒体提取与 Skill/采集链路中的临时 shell 可执行文件只能在 Unix 系统运行，导致 `windows-latest` 的外部命令测试失败，或只能跳过关键成功路径。
- 新增原生 Go ASR 与 ffmpeg 测试夹具，继续从真实子进程边界验证转写 JSON、`HF_HOME` 缓存注入、faster-whisper 离线预检、ffmpeg 输出路径和媒体错误清理。
- Windows 不再跳过媒体转写成功分支；所有测试平台都执行相同的外部命令契约检查。
- 已完成 `go test ./...`、`go vet ./...`、Windows 全仓库交叉编译、原生夹具 Windows 编译与 `git diff --check` 验证。

## Windows 文件系统语义修复与真实 CI 验收

- Windows 的 Chrome/Chromium 可执行文件不提供 POSIX 执行位；浏览器发现现在按 `.exe` 文件语义识别，避免把已配置的 Chrome 错误判定为不可用。
- `XDG_CONFIG_HOME` 作为显式配置根目录覆盖会在所有平台优先处理，Windows 仍在未设置该变量时使用 `%APPDATA%\\DigCrawl`。
- 测试生成的 Windows 文件路径使用正确的 YAML 标量编码，避免反斜杠被解析为转义序列；示例 profile 的跨平台绝对路径占位符也按文档语义校验。
- Cookie 落盘继续执行原子写入与 JSON 完整性验证；仅 POSIX 平台断言 `0600` 文件权限，避免把 Windows 不支持的权限位误判为功能故障。
- 不再只以交叉编译作为验收：已直接读取 GitHub Actions 失败日志并在提交 `e564ca9` 上完成真实 `windows-latest` 验证，`go test ./...`、Windows CDP PowerShell 回归与 Ubuntu job 均成功。
