# 2026-08-03 技能多模态能力与摘要边界更新

## 本次更新

- Skill 在自己的领域内新增媒体下载、OCR、ASR 与视频本地摘要链路，不调用 `collect.Service`，可随本地 MCP 二进制和公开 Skill 指令独立演进。
- OCR 使用 DigCrawl 自己的 OpenAI-compatible 视觉模型客户端；Skill 与 Collect 都通过各自的配置块显式启用，密钥只保留在用户本机 profile。
- ASR 复用 Collect 的配置语义与处理顺序：下载媒体、使用 `ffmpeg` 抽取音频、再调用 API 或本地 `faster-whisper` provider；失败会返回结构化的本地错误，不会把空转写伪装为成功。
- 视频摘要默认由 Codex、Claude Code 等宿主基于 Markdown 和 `asr_text` 完成。`include_summary` 仅保留为用户明确选择的本地 OpenAI-compatible BYOK 兜底，不使用 DigFlow Runtime、DigFlow HTTP 或 extractive fallback。
- Skill 本地 Summary 与 `internal/summary`、DigFlow 包隔离；Collect / Watchlist 原有的 DigFlow Summary 路径保持不变。
- 截图 artifact 保持本地存储并通过 MCP 附件返回；`Gateway.ArtifactMaxInlineBytes` 默认限制为 10 MiB，可由本地 profile opt-in 调整。

## 配置与迁移

- 新增 `Skill.Media`、`Skill.OCR`、`Skill.ASR`、`Skill.Summary` 本地 profile 配置；所有增强能力默认关闭。
- 启用 `Skill.Summary` 时仅接受 `Enabled`、超时与输入预算，以及 `LLM.APIKey`、`LLM.BaseURL`、`LLM.Model`。
- 旧 profile 中的 `Provider`、`FallbackProvider`、`Mode`、`ImportanceThreshold`、`DigFlow` 与 `InputBudget.MetadataChars` 会在加载时明确报迁移错误；禁用的旧 Summary 配置保持惰性，不影响默认宿主总结。
