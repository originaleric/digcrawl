# 2026-11-24 微信视频号短链与本机转写接入更新

本次更新保留在 local/wechat-channels-bridge 本地实验支线。普通视频号分享短链通过本人已登录的腾讯元宝会话解析，复用平台执行器、受限 MP4 下载和本机 ASR。现有桌面卡片捕获继续由原入口管理。

## 读取与登录

原生工具为 `wechat.channels.read`。独立元宝登录由 `browser login --platform wechat_channels --config <profile>` 完成，登录检查和失败提示绑定实际 profile。元宝会话仅在本机专用目录内使用，签名媒体 URL 留在解析与下载内部。

直接读取可以按配置进行转写和帧 OCR；Collect 复用原导出流程。通过 `VideoDownload.Providers.wechat_channels` 可显式启用长期保留。x 的转写路径使用临时 MP4 并返回内容，视频文件不作为其输出附件。

## 下载与预算

部分 CDN 在 HTTP 200 中携带完整实体的 Content-Range。下载器核对完整区间、长度及 MP4 结构后接收，拒绝截断或不完整响应，并保留失败清理与大小上限。新增 MP4 和媒体夹具覆盖真实下载兼容性。

浏览器执行与 Runtime 超时使用同一 OCR 配置选择，覆盖 Skill 默认 OCR、顶层 OCR 回退和网页图片留存。微信原生读取额外计算独立短链解析阶段；截图、下载、ASR 和 OCR 仍各自受配置约束，显式 deadline 优先。

## 本地服务与接入

HTTP 微信视频服务名称为 `digcrawl-wechat`，launchd 标签为 `com.digcrawl.wechat`，使用独立二进制、配置和浏览器目录。原 DigCrawl 安装与服务保留，服务管理复用既有脚本。x 接入使用其专属 MCP Bridge 与固定 binary、profile、工具清单和完整 Skill；更新固定二进制时同步更新 pin，再沿原服务入口重启。

操作见[微信本地使用手册](../docs/微信视频号本地抓取使用手册.md)。仅重启 x 专用 MCP Bridge 时使用同一二进制与 profile 的 `bridge restart`，HTTP Gateway 使用 `scripts/digcrawl-wechat-video-service.sh`。两者按实际安装拓扑管理。
