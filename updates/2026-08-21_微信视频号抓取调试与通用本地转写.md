# 2026-08-21 微信视频号抓取调试与通用本地转写

## 范围与发布边界

今天继续验证 macOS 微信桌面端的视频号桥接。真实客户端的页面加载、媒体请求与版本差异仍使桥接捕获不稳定，因此微信视频号能力继续只保留在本地 `local/wechat-channels-bridge` 分支，不会合并或推送到 `main`。

同时，将已经独立于平台的本地媒体转写能力整理为通用能力：任意本地视频或音频文件都可通过 `digcrawl asr transcribe` 进行转写。该部分会单独进入公开的 `main`，不依赖微信视频号桥接。

## 本次变更

- 本地 ASR 增加隔离运行时安装命令 `digcrawl asr setup --yes`，不修改系统 Python。
- `digcrawl asr transcribe <本地媒体文件>` 支持直接处理任意本地 MP4、MOV、MP3 等可被 ffmpeg 读取的媒体。
- ASR 总时限以 `max(TimeoutSec, 媒体时长 × 2 + 20 秒)` 计算，并由 `MaxTimeoutSec` 提供明确硬上限，避免 Runtime/MCP 的静态 deadline 提前取消长视频。
- 已完成通用 ASR 的单元测试、竞态检查、构建与静态检查；此前下载到本机的测试 MP4 已成功完成本地转写。
- 视频号桥接继续提供 HTML 诊断捕获、页面适配器和本地下载试验入口，但它们仅用于本机研究，不构成已发布能力。

## 当前结论

- “本地文件下载后提取内容”这条链路已与平台解耦，可以作为通用功能发布。
- “从微信桌面端稳定取得并下载当前视频号原视频”尚未通过真实环境验收，不能承诺成功率，也不能作为公开功能发布。
- 完整的本机操作与诊断路径见[微信视频号本地抓取使用手册](../docs/微信视频号本地抓取使用手册.md)。
