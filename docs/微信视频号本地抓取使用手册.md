# 微信视频号本地抓取使用手册（仅本地实验）

> 状态：实验性、本地分支专用，**不随 `main` 发布，也不推送到 GitHub**。它依赖 macOS 微信桌面端的实际行为，当前尚不能保证捕获或下载成功。

## 适用范围

本手册用于研究微信聊天中的视频号视频卡片。桥接在用户明确确认后启动本机回环代理，并通过 PAC 仅将 `*.qq.com` 路由至桥接器；除 QQ 域名外，系统的现有网络与代理设置保持不变。桥接停止时会恢复由 DigCrawl 设置的 PAC 并删除其本地 CA。

桥接不导出微信 Cookie、请求体、响应正文或媒体直链。开启页面适配器后，当前视频的播放地址和可选解密信息仅在正在运行的本地桥接进程内存中使用，以执行一次明确确认的本地下载。

## 准备

1. 在本地视频号分支构建当前二进制：`go build -o digcrawl ./cmd/digcrawl`。
2. 使用真实微信桌面端登录，并准备一条包含视频号视频卡片的聊天消息。
3. 打开两个终端。终端 A 负责保持桥接运行；终端 B 用于导入、下载和转写。
4. 选择一个仅供本次试验使用的状态目录，例如 `/tmp/digcrawl-wechat-channels-test`。同一次试验的所有命令都必须使用同一目录。

不要向桥接提供 Wi-Fi 密码、微信密码或代理密码。带用户名/密码的手动上游代理目前会被拒绝；先停止桥接后再恢复或调整此类代理。

## 1. 启动桥接（终端 A）

```bash
./digcrawl wechat-channels bridge start \
  --yes \
  --state-dir /tmp/digcrawl-wechat-channels-test
```

首次运行可能要求 macOS 授权安装本地 CA 和调整当前网络服务的代理设置。终端 A 必须保持运行；成功后会显示监听地址 `127.0.0.1:20261`。

如需研究页面初始 HTML，可在**绝对路径**显式开启一次诊断捕获：

```bash
./digcrawl wechat-channels bridge start \
  --yes \
  --state-dir /tmp/digcrawl-wechat-channels-test \
  --capture-page-html /tmp/digcrawl-wechat-channels-page.html
```

该 HTML 可能包含敏感页面状态，只保存在本机且文件权限为 `0600`；研究完成后请自行安全处理，不要提交或上传。

## 2. 在微信中触发请求

1. 等待微信被唤起或手动切换到微信。
2. 打开目标聊天中的视频号卡片，点击播放。
3. 等待页面和视频实际开始加载；不要只停留在消息缩略图。
4. 观察终端 A：它会保留捕获统计。若看到 `has not captured a video`，表示本次没有捕获到可导入视频，而不是导入命令本身损坏。

若视频页变成空白、无法播放或网络异常，立即按 Ctrl-C 停止终端 A，再重新打开微信验证网络已恢复。不要在异常状态下重复启动多个桥接器。

## 3. 导入元数据（终端 B，可选）

在同一状态目录中运行：

```bash
./digcrawl wechat-channels import \
  --yes \
  --bridge-state-dir /tmp/digcrawl-wechat-channels-test
```

成功时会先打印当前视频预览，再按配置导出元数据。`404`、`has not captured a video` 或超时都表示当前客户端会话没有提供桥接器可用的当前视频数据；先停止桥接、确认微信可正常播放后再进行一次干净的重新测试。

## 4. 下载当前视频（终端 B，实验性）

下载需要在启动时显式启用页面适配器。终端 A 启动命令应改为：

```bash
./digcrawl wechat-channels bridge start \
  --yes \
  --page-adapter \
  --state-dir /tmp/digcrawl-wechat-channels-test
```

在微信中重新打开并播放目标卡片后，再在终端 B 执行：

```bash
./digcrawl wechat-channels download \
  --yes \
  --bridge-state-dir /tmp/digcrawl-wechat-channels-test \
  --out /Users/dig/Downloads/wechat-channels-test.mp4
```

`--out` 必须是绝对路径。下载不写入元数据导出；播放 URL 与可选解密信息只在终端 A 对应的桥接进程中保留。下载超时或没有捕获到视频时，停止桥接并恢复网络后再诊断；这不是稳定发布能力。

## 5. 对已下载媒体进行本地内容提取

这一步是通用本地 ASR，不依赖微信桥接。首次使用先安装隔离运行时：

```bash
./digcrawl asr setup --yes
```

然后转写本地文件：

```bash
./digcrawl asr transcribe \
  /Users/dig/Downloads/wechat-channels-test.mp4 \
  --provider local \
  --model small \
  --timeout 1200
```

`--timeout` 是本次任务的时间下限；实际预算会结合媒体时长计算，且绝不会超过配置中的 `ASR.MaxTimeoutSec`（默认 1800 秒）。如果视频较长，需要先提高该配置上限，再重新运行。转写完成后可基于输出文本进行摘要、要点和引用整理。

## 6. 始终停止并恢复（终端 A 或 B）

正常结束时优先在终端 A 按 Ctrl-C。若终端 A 已关闭或需要显式恢复，执行：

```bash
./digcrawl wechat-channels bridge stop \
  --state-dir /tmp/digcrawl-wechat-channels-test
```

命令只会恢复仍由本次 DigCrawl 桥接拥有的代理设置并移除其证书。完成后，验证微信视频页和普通网页都能正常打开；如仍异常，先检查 macOS 当前网络服务的 PAC/代理状态，而不要再次启动桥接。

## 快速诊断清单

| 现象 | 首先处理 |
| --- | --- |
| `404` 或 `has not captured a video` | 在微信中实际播放卡片；确认终端 A 未退出；本次状态目录一致；失败后停止并重新开始一次干净会话。 |
| 微信视频页空白或无法播放 | 立即 `bridge stop` / Ctrl-C，确认 PAC 已恢复后再测试。 |
| 下载超时 | 确认启动时使用了 `--page-adapter`，并重新打开、播放视频；仍失败则将其记录为当前客户端不兼容案例。 |
| 本地转写报 `No module named faster_whisper` | 先运行 `./digcrawl asr setup --yes`，不要把依赖安装到系统 Python。 |
| 转写达到时限 | 检查媒体时长和 `ASR.MaxTimeoutSec`；提高硬上限后重试，而不是只反复增大命令行 `--timeout`。 |

## 不要做的事

- 不要将本手册、抓取日志、HTML、媒体、证书或视频号桥接提交到公开分支。
- 不要为了让桥接工作而把全系统流量改到回环代理；设计边界是仅 `*.qq.com`。
- 不要把捕获失败视作绕过平台访问限制的信号；本功能只用于用户已在本机微信中有权打开的内容研究。
