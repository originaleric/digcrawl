# 微信公众号抓取静态解析优先修复方案

## 1. 背景与目标

### 1.1 背景

指定链接 `https://mp.weixin.qq.com/s/TLUaZmr3KC2-W7dcKJKu9g` 的生产式测试结论：

- `digcrawl collect` 走现有浏览器路径时，5 分钟内未返回，最终手动中断。
- 默认 HTTP 请求会被微信重定向到 `/mp/wappoc_appmsgcaptcha` 安全验证页。
- 微信内置浏览器 UA 会重定向到追加 `?nwr_flag=1#wechat_redirect` 的地址。
- 桌面 Chrome UA 可以直接下载完整 HTML，HTML 中存在 `#js_article`、`#activity-name`、`#js_content`、`var msg_title`。
- 因此该 URL 不是死链，失败核心不是“没有文章内容”，而是当前实现过度依赖浏览器动态渲染和完整 `load`。

### 1.2 修复目标

- 公开可访问的公众号文章应优先通过 HTTP HTML 静态解析成功抓取。
- 无法访问或触发风控时，应快速返回结构化错误，不进入长时间浏览器等待。
- 浏览器只作为兜底通道，不再作为微信公众号的唯一读取路径。
- 单条公众号 URL 的失败等待时间应可控，避免 fallback 与 retry 叠加导致十几分钟卡住。

## 2. 根因分析

### 2.1 现有链路问题

当前 `wechat.article.read` 的主要路径：

1. 调用本地浏览器打开公众号 URL。
2. 等待页面 `load`。
3. 等待 `#js_article`、`#js_content`、`#img-content` 等 selector。
4. 从 DOM 提取标题、正文、作者、图片。
5. 校验标题和正文，失败后按 retry/fallback 重试。

关键问题：

- `internal/browser/browser_browse.go` 中 `BrowserBrowse` 会先执行 `page.WaitLoad()`，公众号页面外链资源、脚本、视频、图片和验证逻辑都可能拖住这个阶段。
- `internal/platform/wechat/article.go` 中微信有多个 selector fallback，外层还有 retry；每次 fallback 都可能触发一次完整浏览器超时。
- 公众号 HTML 源码通常已经包含文章正文，但当前没有 HTTP 静态解析路径。
- 风控跳转 `/mp/wappoc_appmsgcaptcha` 没有在 HTTP 或浏览器层快速归类。

### 2.2 这次指定链接的直接证据

通过桌面 Chrome UA 下载到的 HTML 包含：

- 标题：`《我的起源》玩家共创计划开启 珍稀测试资格优先获取！`
- 作者：`腾讯游戏服务中心`
- 正文容器：`#js_content`
- 发布时间变量：`ct = "1557836267"`，页面中也有 `createTime = '2019-05-14 20:17'`

这说明静态 HTML 已足够完成正文抽取，继续等待微信 JS 反而降低稳定性。

## 3. 总体方案

采用三层读取策略：

1. **HTTP 静态 HTML 解析优先**
   - 直接请求文章 URL，解析返回 HTML 中的标题、作者、正文、发布时间、图片。
   - 这是微信公众号的默认主路径。

2. **HTTP 风控与异常快速分类**
   - 在进入浏览器前识别重定向 URL、状态码、响应正文中的微信异常信号。
   - 命中异常时直接返回结构化错误。

3. **浏览器兜底**
   - 仅当 HTTP 静态解析无法确认文章、且未识别为明确异常时启用。
   - 浏览器兜底应收紧等待策略和总超时。

## 4. 详细设计

### 4.1 新增微信 HTTP 静态解析路径

建议在 `internal/platform/wechat/article.go` 中把 `ReadArticle` 调整为：

1. `readArticleHTTP(ctx, in, url)`
2. 若 HTTP 解析成功，返回 `platform.Content`
3. 若 HTTP 明确识别风控、删除、私有、登录等，返回结构化 `platform.ReadError`
4. 若 HTTP 不确定，再进入现有 `readArticleBrowser`

新增文件建议：

- `internal/platform/wechat/http_client.go`
- `internal/platform/wechat/html_parser.go`
- `internal/platform/wechat/html_parser_test.go`

解析字段：

- `title`
  - 优先：`#activity-name .js_title_inner`
  - 兜底：`#activity-name`
  - 再兜底：`var msg_title = '...'`

- `author`
  - 优先：`#js_name`
  - 兜底：`var nickname = htmlDecode("...")`

- `published_at`
  - 优先：`#publish_time` 文本
  - 兜底：`createTime = 'YYYY-MM-DD HH:mm'`
  - 再兜底：`ct = "unix_timestamp"`

- `text`
  - 从 `#js_content` 提取纯文本
  - 去除多余空白、脚本、样式和隐藏诊断内容

- `markdown`
  - 将 `#js_content` HTML 转 Markdown
  - 保留链接、图片占位、段落结构

- `media`
  - 收集 `#js_content img[data-src]`
  - 兜底 `src`
  - 去重并过滤 `data:` URL

输出契约：

- `platform.Content.HTML` 必须写入清洗后的 `#js_content` HTML。
- `platform.Content.Markdown` 必须由同一份清洗后的正文 HTML 转换而来。
- `platform.Content.Text` 必须由同一份正文 DOM 提取纯文本。
- `platform.Content.Media` 必须从同一份正文 DOM 的图片节点提取。
- `HTML`、`Markdown`、`Text`、`Media` 四者必须同源，避免 JSON 成功但 `--format html` 为空，或媒体列表与 HTML 图片不一致。
- 如果正文 HTML 中的图片使用 `data-src`，写入 `Content.HTML` 前应同步补齐或替换为可下载的 `src`，确保 `collect/assets.go` 的 HTML 图片扫描与 `Media` 列表一致。

### 4.2 HTTP 请求策略

HTTP 请求配置建议：

- Timeout：15-20 秒
- User-Agent：桌面 Chrome UA
- Accept：`text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8`
- Accept-Language：`zh-CN,zh;q=0.9,en;q=0.8`
- 自动解压 gzip/br/deflate
- 限制最大响应体，例如 8-12MB
- 允许重定向，但保留重定向链用于诊断

HTTP 阶段不新增 `HTTP_FETCH_FAILED` 平台错误码。现有平台错误码仍以 `internal/platform/errors.go` 为准：

- 明确业务异常必须返回现有结构化 `ReadError`。
- 网络、超时、响应损坏等 transient 错误只作为“是否进入浏览器兜底”的内部原因写入 metadata，不对外暴露新错误码。
- 如果后续确实需要 `HTTP_FETCH_FAILED`，必须先扩展 `internal/platform/errors.go`、fatal/retry 语义、collect 错误处理和对应测试，本轮不做。

HTTP 失败与兜底决策：

| HTTP 阶段结果 | 处理 | 对外错误码 | 是否进入浏览器兜底 |
| --- | --- | --- | --- |
| 正常解析出有效标题和正文 | 成功返回 | 无 | 否 |
| 重定向链或最终 URL 命中 `/mp/wappoc_appmsgcaptcha` | 直接失败 | `CAPTCHA_REQUIRED` | 否 |
| HTML 正文命中安全验证/验证码文案 | 直接失败 | `CAPTCHA_REQUIRED` | 否 |
| HTML 正文命中环境异常/访问频繁文案 | 直接失败 | `RATE_LIMITED` | 否 |
| HTML 正文命中微信客户端/登录态提示 | 直接失败 | `LOGIN_REQUIRED` | 否 |
| HTML 正文命中删除/违规不可看 | 直接失败 | `CONTENT_DELETED` | 否 |
| HTML 正文命中关注后可见/不可见 | 直接失败 | `CONTENT_PRIVATE` | 否 |
| HTML 正文命中页面不存在/链接失效 | 直接失败 | `CONTENT_NOT_FOUND` | 否 |
| HTTP timeout、DNS、连接失败、5xx | 记录 `http_error` 后兜底 | 无 | 是 |
| 响应体超过最大限制 | 记录 `http_error=response_too_large` 后兜底 | 无 | 是 |
| HTML 可解析出标题但正文为空/过短，且未命中明确异常 | 记录 `http_parse_state=partial` 后兜底 | 无 | 是 |
| HTML 无法解析为文章，且未命中明确异常 | 记录 `http_parse_state=unclassified` 后兜底 | 无 | 是 |
| HTTP 不确定且浏览器兜底也失败 | 返回浏览器阶段结构化错误；若仍无法归类，返回 `SELECTOR_STALE` 或 `PARTIAL_CONTENT` | 现有错误码 | 不再继续 |

### 4.3 风控与异常快速分类

在 HTTP 阶段识别：

| 信号 | error_code | 处理 |
| --- | --- | --- |
| 重定向 URL 包含 `/mp/wappoc_appmsgcaptcha` | `CAPTCHA_REQUIRED` | 直接失败 |
| 正文包含 `安全验证` / `验证码` | `CAPTCHA_REQUIRED` | 直接失败 |
| 正文包含 `环境异常` / `访问过于频繁` | `RATE_LIMITED` | 直接失败 |
| 正文包含 `请在微信客户端打开` / `请使用微信打开` | `LOGIN_REQUIRED` | 直接失败 |
| 正文包含 `该内容已被发布者删除` / `文章已删除` | `CONTENT_DELETED` | 直接失败 |
| 正文包含 `此内容因违规无法查看` | `CONTENT_DELETED` | 直接失败 |
| 正文包含 `以下内容需要关注后才能查看` | `CONTENT_PRIVATE` | 直接失败 |
| 正文包含 `页面不存在` / `链接已失效` | `CONTENT_NOT_FOUND` | 直接失败 |

`platform_metadata` 至少保留：

- `read_channel`: `http`
- `extraction_source`: `html`
- `http_status`
- `final_url`
- `redirect_chain`
- `page_state`
- `error_code`
- `error_message`
- `warnings`
- `http_error`，仅在 HTTP transient 失败或解析不确定时写入
- `http_parse_state`，取值如 `ok` / `partial` / `unclassified`

### 4.4 成功质量判定

禁止“空成功”。HTTP 与浏览器路径统一执行质量校验。

标题无效集合：

- 空字符串
- `Weixin Official Accounts Platform`
- `微信公众平台`
- `Official Accounts`

正文判定：

- `text_len >= 120` 且标题有效：成功
- `40 <= text_len < 120` 且标题、作者、正文容器至少 2 项存在：降级成功，并写入 `warnings`
- `text_len < 40`：失败，返回 `PARTIAL_CONTENT`
- 标题无效且无法从 `msg_title` 回填：失败，返回 `SELECTOR_STALE`

成功结果 metadata：

- `read_channel`
- `extraction_source`
- `body_text_length`
- `title_source`
- `author_source`
- `published_at_source`
- `image_count`
- `canonical_url`

### 4.5 浏览器兜底优化

浏览器兜底保留，但需要降成本。本轮所有浏览器优化都限定在微信读取链路内，不修改通用 `BrowserBrowse` 的默认语义，避免影响小红书、抖音、头条和 X。

- P1 阶段先给 `wechat.article.read` 增加总超时，并减少微信 selector fallback 成本。
- P1 阶段不直接改 `internal/browser/browser_browse.go` 的通用 `page.WaitLoad()` 行为。
- 如需跳过完整 `load`，应新增微信专用浏览器读取函数或显式参数，并用其他平台回归测试保护。
- 微信浏览器路径不要无条件等待完整 `load` 后才看正文。
- 优先等待 `#activity-name, #js_content, #js_article` 中任一 selector。
- 减少 selector fallback 数量，优先：
  - `#js_article`
  - `#js_content`
  - `#img-content`
- 给 `wechat.article.read` 设置单 URL 总超时，例如 60-90 秒。
- 如果最终 URL 或页面文本命中风控信号，立即返回结构化错误。

浏览器 metadata：

- `read_channel`: `browser`
- `browser_latency_ms`
- `matched_selector`
- `final_url`
- `page_title`
- `body_text_length`
- `warnings`

## 5. 实施步骤

### 第一步：抽出 HTML 解析器

交付内容：

- 新增 `parseArticleHTML(rawHTML, sourceURL)`。
- 使用结构化 HTML parser，不使用大段正则处理 DOM。
- 仅对 `var msg_title`、`var nickname`、`ct/createTime` 等脚本变量使用小范围正则兜底。

验收：

- 能从本次保存的 `direct-desktop.html` 提取真实标题、作者、正文和图片。
- `platform.Content.HTML`、`Markdown`、`Text`、`Media` 来自同一份清洗后的正文 DOM。
- 离线单测不依赖网络。

### 第二步：实现 HTTP 读取器

交付内容：

- 新增 `readArticleHTTP(ctx, in, url)`。
- 支持 UA、超时、最大响应体、重定向链记录。
- 接入异常快速分类。

验收：

- 正常 HTML 返回 `platform.Content`。
- `/mp/wappoc_appmsgcaptcha` 风控跳转固定返回 `CAPTCHA_REQUIRED`。
- 访问频繁/环境异常文案固定返回 `RATE_LIMITED`。
- 删除/私有/不存在 fixture 返回对应错误码。

### 第三步：调整 `ReadArticle` 编排

新顺序：

1. HTTP 静态解析
2. HTTP 明确异常直接失败
3. HTTP 不确定再浏览器兜底
4. 浏览器结果统一质量校验

验收：

- 指定 URL 优先走 HTTP，不进入浏览器长等。
- 仍兼容需要浏览器渲染的特殊文章。

### 第四步：收紧浏览器兜底

交付内容：

- 给微信读取增加总超时控制。
- 减少 fallback 成本。
- 遇到安全验证 URL 或文案快速失败。

验收：

- 单条失败 URL 不再超过设定总超时。
- 不再出现十几分钟卡住。

### 第五步：补测试和回归

新增 fixture：

- `article_ok.html`
- `article_hidden_content.html`
- `article_placeholder_title.html`
- `captcha_required.html`
- `content_deleted.html`
- `content_private.html`
- `content_not_found.html`

fixture 来源与脱敏策略：

- 不直接提交完整 `direct-desktop.html`，避免 2.9MB 大文件、版权内容和维护噪音进入测试资产。
- 从 `direct-desktop.html` 裁剪最小真实结构 fixture，保留：
  - `#activity-name`
  - `#js_name`
  - `#publish_time`
  - `#js_content`
  - `var msg_title`
  - `var nickname`
  - `ct` / `createTime`
- 将真实公众号名、正文长段、图片 URL、token、biz、mid、sn、req_id 等替换为固定测试占位值。
- 保留微信真实 DOM 层级和 `data-src` 图片属性，以覆盖真实解析路径。
- 人工构造异常页 fixture 时，只保留触发分类所需的最小 HTML 和关键文案。

测试范围：

- HTML parser 单测
- HTTP 读取器单测
- 风控分类单测
- `ReadArticle` 编排单测
- 真实 URL CLI 复测

命令：

## 6. 验收标准

### 6.1 成功样例

对公开文章：

- CLI 在合理时间内返回成功。
- JSON 包含真实 `title`、`text`、`markdown`。
- Markdown 包含标题、来源和正文。
- `platform_metadata.read_channel=http`。
- `platform_metadata.body_text_length > 120`。

### 6.2 失败样例

对风控、删除、私有、失效文章：

- 不落空正文成功文件。
- 返回结构化错误码。
- metadata 中包含 `final_url`、`page_state`、`error_message`、`warnings`。
- 单条 URL 不超过总超时。

### 6.3 回归

- `go test ./...` 通过。
- 既有微信重试测试继续通过。
- 小红书、抖音、头条、X 的读取路径不受影响。

## 7. 风险与取舍

- 静态解析依赖微信 HTML 结构，但 `#activity-name`、`#js_content`、脚本变量是公众号文章长期稳定信号，风险低于纯浏览器等待。
- 少数强依赖 JS 后渲染的内容可能仍需要浏览器兜底。
- 使用桌面 Chrome UA 可能遇到微信策略变化，因此保留浏览器兜底和结构化错误分类。
- 不建议绕过验证码或安全验证；应识别并返回 `CAPTCHA_REQUIRED` / `RATE_LIMITED`，交给上游决定是否人工处理。

## 8. 推荐实施优先级

1. P0：HTML 静态解析器和 fixture 单测。
2. P0：HTTP 读取器与风控快速分类。
3. P1：`ReadArticle` 编排接入 HTTP 优先。
4. P1：微信浏览器兜底总超时和 selector 成本收敛。
5. P2：失败诊断 artifact、截图和 HTML 快照增强。

按此方案实施后，当前指定链接应从“浏览器长时间卡住”变为“HTTP 静态解析快速成功”；对于真实风控页，也能快速返回结构化错误。
