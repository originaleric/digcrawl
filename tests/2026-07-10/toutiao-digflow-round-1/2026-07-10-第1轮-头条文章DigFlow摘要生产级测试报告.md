## 输出质量评估

目标输出未生成。原因不是 DeepSeek / DigFlow runtime，而是前置文章正文抓取失败：

- 项目真实抓取路径需要浏览器兜底。
- 当前环境无法启动 Chromium 或系统 Chrome headless/CDP。
- HTTP/API 降级没有拿到正文，只拿到壳页或 404。

因此本轮未调用 DigFlow runtime agent，也未调用 DeepSeek API，避免基于空正文生成伪摘要。

## Findings

### [P1] 当前测试环境无法启动浏览器，导致头条文章抓取主链路失败

位置 / 命令：

- `go run ./cmd/digcrawl collect ...`
- `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --dump-dom https://example.com`

复现：

1. 默认 collect 路径触发 Rod 自动下载 Chromium。
2. 下载/解压后仍报 `can't find a browser binary for your OS`。
3. 指定系统 Chrome 后报 `Failed to get the debug url`。
4. 直接执行 Chrome headless dump DOM 也失败。

期望：

- DigCrawl 能启动可调试 Chromium/Chrome，进入头条页面并提取正文。

实际：

- 浏览器运行环境不可用，头条采集失败。

修复方向：

- 在测试机安装并验证可 headless 启动的 Chromium/Chrome。
- 或启动一个稳定的外部 Chrome CDP 实例，并在 `LocalBrowser.CDPConnectExisting=true` 下复测。
- 复测前先确认：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --remote-debugging-port=9222 \
  --user-data-dir=/tmp/digcrawl-chrome-profile about:blank

curl http://127.0.0.1:9222/json/version
```

### [P2] 头条公开 HTTP/API 降级不能独立取得正文

位置 / 命令：

- `toutiao-http.html`
- `toutiao-api-v2.json`
- `toutiao-api-info.json`

复现：

- 直接 curl 文章 URL 返回 JS 壳页。
- `article/v2/index` 返回 JS 壳页。
- `group/article_info` 返回 404 HTML。

期望：

- 至少一个无浏览器降级路径能返回正文 JSON 或 hydration 数据。

实际：

- 无法从 HTTP/API 响应中抽取标题与正文。

修复方向：

- 继续依赖浏览器上下文 fetch，优先修复浏览器运行环境。
- 后续可补一个“壳页检测 + 明确错误”的测试用例，避免误把壳页当正文。
