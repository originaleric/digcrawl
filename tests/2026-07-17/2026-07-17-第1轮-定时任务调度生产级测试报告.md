# 2026-07-17 第1轮 定时任务调度生产级测试报告

## 结论

本轮结论：`PARTIAL / BLOCKED`。

已验证通用 Task runtime 的 SQLite schema、索引和基础写入路径可用；真实平台 HTTP 探测显示头条作者页和 X/Elon 页面均可达。但未能完成 `digcrawl watchlist serve` 的真实常驻调度执行，因为当前机器执行 `go run ./cmd/digcrawl ...` 时长时间卡在全量依赖编译/下载阶段，超过 3 分钟仍未进入 CLI 逻辑。

同时发现当前 Watchlist feed registry 代码层面尚不支持 `x` 平台账号 watchlist，因此即使编译通过，`Tasks` 中配置 `Platform: x` / `Kind: user` 也会走到 `unsupported watchlist platform "x"`。

## 测试目标

- 使用生产级方式验证新定时能力：
  - `Tasks` 配置能表达不同扫描周期。
  - `watchlist serve` 使用 `dc_task_*` runtime 表。
  - SQLite 本地持久化可初始化、写入 runtime 状态。
  - 尝试使用真实头条作者页和 X/Elon 页面。
- 不验证真实 Feishu 通知，本轮配置中关闭通知，避免误推送。
- 不写入真实生产数据库，使用测试目录内 SQLite 文件。

### 1. 识别定时任务入口

证据：

- `cmd/digcrawl/watchlist_cmd.go` 中 `watchlist serve` 会加载配置、校验 `Watchlist.Enabled` 与 `Watchlist.Scheduler.Enabled`，然后循环调用 `svc.RunDue(ctx, time.Now())`。
- `internal/watchlist/service.go` 中 `RunDue` 会同步 task 定义到 `dc_tasks_runtime`，判断 `IsTaskDue`，再进入 `runScheduledTask`。
- `runScheduledTask` 会写入 `dc_task_runs` 和 `dc_task_events`，并调用现有 `RunItem`。

## Findings

### P1: 当前环境无法完成真实 `watchlist serve` 生产执行

位置/命令：

- `go run ./cmd/digcrawl version`
- 预期下一步为 `go run ./cmd/digcrawl watchlist serve --config tests/2026-07-17/scheduler-prod-round-1/config.watchlist.yaml`

复现：

- 使用可写 `GOMODCACHE=/private/tmp/digcrawl-gomodcache` 和 `GOCACHE=/private/tmp/digcrawl-gocache`。
- `go run ./cmd/digcrawl version` 超过 3 分钟未进入 CLI 输出。

期望：

- CLI 能在可接受时间内启动，随后执行 `watchlist serve` 并在 `dc_task_*` 表中产生真实 run/event。

实际：

- 当前测试环境卡在依赖下载/编译阶段，无法验证真实调度主循环。

修复方向：

- 在本机先执行一次稳定构建，产出本地 `digcrawl` 二进制用于测试。
- 或为生产测试提供预编译二进制/CI 缓存，避免每轮测试重新编译 DigFlow、go-rod 等重依赖。

### P1: Watchlist 当前不支持 X/Elon 账号作为定时来源

位置：

- `internal/watchlist/feed.go`

证据：

- `FeedRegistry.ListLatest` 支持 `rss`、`sitemap`、`toutiao`、`douyin`、`reddit`、`web`。
- 没有 `platform == "x"` 或 `platform == "twitter"` 分支。
- 默认分支返回 `unsupported watchlist platform %q`。

期望：

- 用户配置 `Tasks[].Source.Platform: x`、`Kind: user`、`URL: https://x.com/elonmusk` 后，watchlist 能读取 Elon Musk 最新内容。

实际：

- 当前代码会拒绝该平台，无法进入 X 抓取。

修复方向：

- 为 Watchlist 增加 X 来源 reader：
  - `x_user`：读取用户主页最新 posts，优先 API，fallback oEmbed/浏览器。
  - 或先支持 `x_post` 固定帖子 URL 监控。
- 明确配置 schema：`Source.Kind: x_user | x_post`，并在 `USAGE.md` 中注明 X 账号监控的鉴权前置。

### P2: 头条作者页 HTTP 可达但当前 HTML 链接发现策略可能抓不到文章

位置：

- `internal/watchlist/feed.go`
- `readHTMLLinks`

证据：

- 测试 URL 返回 `HTTP/2 200`，HTML 4911 bytes。
- 当前 HTML 中未匹配到 `/article/` 或 `/group/` 链接。

期望：

- 头条作者页作为 watchlist 来源时能发现最新文章。

实际风险：

- `readHTMLLinks` 只从静态 `href` 中提取文章链接；如果头条作者页通过 hydration/API 动态加载文章列表，本轮探测页面不会产出 feed items。

修复方向：

- 为头条作者页增加平台专用 API/hydration 解析，或使用 headless 渲染后提取链接。
- 对作者页发现失败增加更明确的错误信息和诊断字段。
