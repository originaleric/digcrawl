## Findings

### P1: Watchlist service 子包引用了另一个包内的未导出 helper，导致 CLI 无法编译

- 位置：
  - `internal/watchlist/service/service.go`
  - `internal/watchlist/helpers.go`
- 复现：
  - `go test ./internal/watchlist/service -count=1`
  - `go build ./cmd/digcrawl`
  - `go run ./cmd/digcrawl watchlist run --once --config tests/2026-07-17/watchlist-prod-round-6/config.watchlist.yaml`
- 实际结果：
  - `service.go` 使用 `firstNonEmpty` 和 `optionString`
  - 这两个函数实际定义在 `internal/watchlist/helpers.go`，包名是 `watchlist`
  - `internal/watchlist/service` 是独立子包，不能访问 `watchlist` 包内未导出的函数
- 预期结果：
  - `internal/watchlist/service` 子包自身可独立编译，CLI 能构建并进入 `watchlist run --once`
- 系统影响：
  - 当前状态下 Watchlist 的真实入口仍不可用。
  - `internal/watchlist` 包测试通过会掩盖子包编译失败，后续测试矩阵必须覆盖 `./internal/watchlist/service` 或直接 `go test ./...` / `go build ./cmd/digcrawl`。
- 修复方向：
  - 从系统层面看，这是 package split 后 helper ownership 没有同步迁移的问题。
  - 建议不要只在调用点零散改名；应统一决定这些 helper 属于 `internal/watchlist/service`、公共 utility，还是通过已导出的 `watchlist` API 暴露。
  - 最小安全修复通常是把 `firstNonEmpty` / `optionString` 放到 `internal/watchlist/service` 包内，或改为该包已有等价 helper，避免跨包依赖未导出符号。
  - 修复后必须重跑：
    - `go test ./internal/watchlist/service -count=1`
    - `go build ./cmd/digcrawl`
    - `go run ./cmd/digcrawl watchlist run --once --config tests/2026-07-17/watchlist-prod-round-6/config.watchlist.yaml`
