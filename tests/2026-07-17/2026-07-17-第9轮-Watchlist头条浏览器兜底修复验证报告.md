# 2026-07-17 第9轮 Watchlist 头条浏览器兜底修复验证报告

## 结论

本轮针对第6轮后续暴露的头条 collect 失败进行分析和修复。根因不是头条 source 或 collect 主链路失效，而是本机浏览器 fallback 启动策略不够稳健：

1. `LocalBrowser.ChromePath` 为空时，代码直接交给 go-rod 自动查找/下载浏览器。
2. go-rod 在当前 macOS sandbox 环境未稳定使用本机可用浏览器，先尝试下载 Chromium snapshot，失败后报 `can't find a browser binary`。
3. 增加系统 Chrome 自动发现后，代码能找到 `/Applications/Google Chrome.app/...`，但系统 Chrome 在 sandbox/headless 下失败：`Failed to get the debug url`。
4. 本机已安装 Playwright `chrome-headless-shell`，这是 README/USAGE 推荐的兜底路径；但代码之前不会自动优先使用它，也不会自动补 macOS sandbox 需要的启动参数。

修复后，clean round-9 真实 watchlist dry-run 通过：头条和 X 均 `discovered=1 new=1 collected=1 summarized=1 notified=1 errors=`。

## 代码修复

- `internal/browser/browser_pool.go`
  - `normalizeLocalBrowserConfig` 在 `ChromePath` 为空时自动发现本机浏览器。
  - 发现顺序：显式环境变量 `DIGCRAWL_CHROME_PATH` / `CHROME_PATH` / `CHROME_BIN` > Playwright `chrome-headless-shell` > 系统 Chrome/Chromium/Edge/Brave > PATH 命令。
  - 对 `chrome-headless-shell` 自动补兼容参数，macOS 下包含 `--single-process`、`--no-zygote`、禁用 crashpad/breakpad 等。
- `internal/browser/browser_pool_test.go`
  - 覆盖显式 `ChromePath` 不被覆盖。
  - 覆盖环境变量路径。
  - 覆盖 Playwright headless shell 自动发现。
  - 覆盖 headless shell 兼容参数不会重复注入。
