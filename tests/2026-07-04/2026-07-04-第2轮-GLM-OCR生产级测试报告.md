## Findings

[P2] 下载图片文件名可能保留非图片扩展，导致智谱 `files/ocr` 拒绝

Location/Command:
- `collect/assets.go:275`
- 失败产物: `tests/2026-07-04/glm-ocr-prod-round-2/local-output/generated-invoice-baseline/2026-07-04/Generated invoice OCR baseline local-files-ocr.assets/001.50`

Reproduction:
1. 使用图片 URL: `https://dummyimage.com/900x260/ffffff/000000.png&text=Invoice+No+20260704+Amount+USD+128.50`
2. `DownloadMedia=true`
3. 下载得到真实 PNG 文件，但 asset 文件名生成成 `001.50`
4. `zhipu_ocr` 本地路径上传到 `files/ocr`
5. 智谱返回 `OCR provider HTTP 400`

Expected:
- 下载后的本地图片应使用可被 OCR provider 接受的图片扩展名，例如 `.png` / `.jpg`。
- 当 URL path 扩展不可靠时，应优先根据响应 `Content-Type` 或文件内容推断扩展名。

Actual:
- `assetFilename` 只从 URL path 取扩展名，遇到带文本参数样式的图片 URL 时，把 `.50` 误作为扩展名。
- 本地文件内容是 PNG，但文件名不是图片扩展，导致 `files/ocr` 上传失败。

Suggested direction:
- 在下载资产时把 HTTP `Content-Type` 纳入文件扩展名决策，或下载后根据 magic bytes / detected content type 修正扩展名。
- 增加测试覆盖：URL path 扩展不可靠但响应为 `image/png` 时，本地文件必须保存为 `.png`，并能被 `zhipu_ocr` 本地上传路径识别。
