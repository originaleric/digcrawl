## 系统分析与修复边界

等级 B。两个 Findings 的共同问题是交付边界只相信当前字段，没有确认这些字段代表已完成的读取及允许的实际来源。修复分别放在既有 browser 读取边界和 provider 策略边界：browser 判断一次提取是否跨了页面，provider 判断实际来源是否符合本次调用策略。

browserManager 继续拥有连接、页面租约、槽位和清理；browseRetryState 继续拥有请求预算及最多一次浏览器故障重放。本轮文档信息仅保存在当前读取的局部变量中。复用既有 CDP 查询、BrowseError、diagnostics、validatePlatformURL、平台元数据字段及 Feed 的 Client 选项，没有新增生产类型、接口、管理器、配置项、持久化状态或领域抽象。

入口分析发现平台共享 handler 和 Reddit 独立 handler 都处理 Content，但 SourceURL 常保留原始输入。仅在共享 handler 检查 SourceURL 会漏掉独立入口及真实地址的透传，因此一并覆盖 SourceURL、final_url、resolved_url，并由平台 Browse 保留浏览器确认的实际地址。Feed 也经过同一 handler，其 HTTP 跳转地址通过既有 Client 选项保留。

## 修复内容

1. **P2 页面切换造成内容来源错配：已修复。** BrowserBrowse 在提取前后比较实际 URL 和主文档 frame/loader；SPA 路径、query、fragment 切换，以及同 URL 重载均拒绝交付。最终 URL 不再覆盖旧正文的来源。返回已有 BROWSER_CONTENT_NOT_FOUND，stage=read_page、reason=page_changed，提示用户或 Agent 等页面稳定后重新读取。没有在页面切换时添加自动重放或 selector fallback；正文、Markdown、截图、摘要、快照及元数据作为本次结果一起丢弃。正常加载阶段的跳转和同页面标题更新仍可成功。
2. **P2 平台结果绕过最终域名约束：已修复。** 平台共享 handler 和 Reddit handler 在增强、媒体保存、截图 artifact 和输出之前检查实际来源。既有校验函数支持一起检查已知的实际地址，继续采用 call > config > 平台默认的优先级。空 Content 或缺失 SourceURL 明确拒绝，避免无法确认来源的成功。普通浏览器 provider 继续使用上一轮的最终 URL 校验。
3. **地址透传：已补齐。** 所有经过平台 Browse 的浏览器响应，将已确认 URL 写入既有 final_url 字段，覆盖页面脚本声明的地址；保留原输入作为 SourceURL 的适配器也能受最终来源检查约束。Feed 保留 HTTP 实际跳转地址，并维持原有 20 秒超时与十次跳转上限。媒体 CDN、文章内链接及 canonical 引用不作为此次页面来源检查对象。
4. **快照出口：验收发现并修复。** 共用 FetchAXTree 的两个 Accessibility 请求原先发送到空 session；改为当前页面 session。实际 MCP 又发现 browser.browse 丢弃已提取的 Elements，补齐现有字段透传，空快照返回空数组。没有新增接口或快照领域。内部真实 Chrome 和实际 MCP 均能返回 fixture 按钮。
5. **错误指引与诊断：已补齐。** 页面切换给出 retry_read 指引，记录 error/page_changed，保持 handled=true、retryable=false、retry_count=0。请求取消及预算耗尽仍优先采用既有终止规则。

本轮生产修复限定九个既有文件，独立于先前未提交修改的差异保存在 [生产修复 patch](第6轮生产修复.patch)。
