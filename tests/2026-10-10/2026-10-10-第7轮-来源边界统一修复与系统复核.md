# 2026-10-10 第7轮 来源边界统一修复与系统复核

## 结论与边界

等级 B。三项 P2 按共同来源不变量修复：页面数据由获取层确认实际来源，合并保留该来源，交付层在增强、下载、保存和输出前验证本次调用策略。快照共用既有 BrowserBrowse 生命周期；Feed 与 Reddit RSS 共用获取层的实际 HTTP 来源；B站接受浏览器媒体时保留确认来源。系统复核另外发现错误元数据也可能携带正文，因此一并覆盖成功与结构化错误出口。

生产修改限定十一个既有文件，差异独立保存在 [第7轮生产修复.patch](第7轮生产修复.patch)。没有新增生产类型、接口、helper、manager、配置项、状态机、持久化状态或领域。既有 Browse DTO 增加内部快照选项及 refs，既有 Reddit ListingResult 增加仅内部使用的 SourceURL；均复用现有快照/来源契约，不新增公开参数或来源抽象。保留先前未提交修改，未提交或推送。

## 系统分析与入口清单

- 浏览器：browser.browse 的 full/summary/snapshot/screenshot、独立 browser.snapshot、内部平台 Browse。独立快照删除自行获取、导航和释放的旧路径，只适配既有请求/响应；相同 owner、请求截止时间、最多一次故障重试、文档一致性、错误指引和释放规则。保留独立快照的 LocalBrowser 域名约束及 filter/max_depth/refs；provider 再检查实际 URL 的 call/config 策略。
- RSS：Feed.Service.Fetch 返回最终 response.Request.URL；Read/ReadSitemap 将其保存在已有 Document.URL；ToContent 写入已有 final_url。删除 feed.read 自行追踪 redirect 的包装。Reddit 帖子、subreddit、user 三条 RSS 路径都从同一个 Document 获得实际来源；provider 帖子及列表入口验证后输出。配置的 API 后端仍采用既有 API 契约，不把 API endpoint、CDN 或条目链接误作此次页面来源。
- B站：API 保留标题、正文、作者、指标等权威内容。无新增视频时不修改来源；有新增视频时先要求确认来源，再合并视频与 final_url，provider 检查后才进入下载/增强/保存。无法确认来源时不先改变 API 结果。
- 错误输出：共享 platform handler 和 Reddit handler 的 ReadError 分支对已知 final_url/resolved_url 使用同一 validatePlatformURL；拒绝越界元数据，允许来源仍返回原有结构化错误与信息。
- 其他消费者：Fetch 现有三个调用点均调整，watchlist 的 RSS/sitemap 使用已有 Document，HTML 原始抓取只适配返回签名。browser.action 属于已审批交互，PageFetch 属于既有 API 调用，没有重放或状态所有权变更。

不变量的 owner 没有变化：manager 管连接/租约/target，browseRetryState 管调用预算和重试，Feed 的 HTTP 获取层管实际响应地址，平台 adapter 管 Content 合并，provider 管本次调用策略。没有第二个恢复 owner 或新的跨调用状态。
