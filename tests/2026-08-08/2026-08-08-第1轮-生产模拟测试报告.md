## 4. 执行记录

| 步骤 | 命令/API | 结果 | 关键证据 |
| --- | --- | --- | --- |
| 1 | MCP `toutiao.video.read`，`include_media=true` | 失败 | 返回 `PARTIAL_CONTENT`；标题等元数据可读，但没有 video media URL。 |
| 2 | 修正通用浏览器媒体探测后再次 MCP 读取 | 阻塞 | 播放器探测触发页面会话要求，返回 `LOGIN_REQUIRED`。 |
| 3 | `digcrawl browser check --platform toutiao --trial` | 非验收路径 | 当前 check 使用文章 reader，视频 URL 返回 `CONTENT_TYPE_MISMATCH`，不能据此判断视频会话。 |

| 5 | MCP `toutiao.video.read`，`include_media=true`、`include_asr=true` | 首次失败 | 配置的 ASR 临时目录不存在；已改为运行时自动创建。 |

| 8 | Review 后的真实 profile `digcrawl doctor` | 通过 | ffmpeg、本地 ASR command 与 MCP 初始化均通过；缺少依赖的全新临时 profile 已由自动化测试验证会拒绝启用且不写入 opt-in。 |

## 6. Findings

本轮发现并修复两项端到端阻塞：

1. 配置的 ASR 临时目录不存在时，音频提取无法创建工作目录；现在运行时会创建该目录。
2. MCP 使用 Runtime 的通用 60 秒默认时限，无法覆盖显式本地 ASR 的配置时限；现在普通读取沿用 Collect 的浏览器预算，显式 ASR/本地视频总结额外纳入下载、ASR（及总结）预算。

修复后已通过同一真实头条视频的媒体发现、下载和本地 ASR 验收。
