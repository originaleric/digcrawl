# 2026-11-26 v1.0.6 本地发布准备验收

版本从 1.0.5 顺延至 1.0.6，npm 安装器与 Go Release v1.0.6 配对。环境为 macOS arm64、Node 20.19.3、npm 11.21.1、Go 1.26.1。

## 已完成的本地检查

- 微信源码合并前全量 go test ./...、相关 go vet 和 CLI 构建通过。
- npm ci --ignore-scripts、npm test、npm audit --omit=dev 均通过，实际 tarball 白名单由安装器测试核验。
- 服务 shell 语法、真实 macOS plutil 与强制模拟解析器的完整生命周期回归均通过。
- 服务夹具使用原生临时目录，非 macOS 主机统一模拟 plist 工具；实际 macOS 保留原生工具校验。
- README 中英文、USAGE、微信手册及完整截图流程已核对，联系人脱敏素材与用户授权的头像展示保持一致。
- .gitignore 及 npm/cli.mjs 的既有工作区修改保持原样，不纳入本次提交；没有强制 add，运行目录和私有验收输出保留本地。

## 发布与远端验收

按用户要求，最终提交推送后执行已有 Test workflow 的 Linux、macOS、Windows 三平台，并核对实际 head_sha 和必需步骤。通过后创建新 v1.0.6 tag，由现有 Release workflow 发布五个平台安装包和 checksums.txt；校验公开下载后发布 npm 1.0.6。最终运行与发布结果链接由交付记录提供，原始日志保留本地。

## 首轮 CI 与兼容修复

首轮 [Test](https://github.com/originaleric/digcrawl/actions/runs/45809696491) 的 Linux 与 macOS 通过，Windows 在 `bridge.go` 编译时报 `undefined: syscall.Kill`。微信桥接的 owner 存活检查改为复用现有 `browser.ProcessAlive` 平台实现；无法确认 owner 状态时保留恢复资源，不抢占清理。相关桥接与浏览器测试、完整 go test ./...、全包 go vet、Windows 全包交叉构建通过；交叉构建只作为构建证据，最终三平台运行仍核对修复后提交的完整 Test。

## 第二轮 CI 的平台边界

第二轮 [Test](https://github.com/originaleric/digcrawl/actions/runs/45810695152) 的 Linux、macOS 通过。Windows 已通过编译，但完整测试暴露三处 POSIX 权限位断言，以及元宝登录测试中硬编码 Unix 路径的问题。检查完整微信命令、诊断文件及登录提示后，按已有仓库惯例将 POSIX 权限位断言限定于非 Windows；Windows 继续执行路径、目录类型、内容及脱敏断言，本轮不宣称已验证 Windows ACL。

登录提示在 Windows 使用 PowerShell 的字面量路径与单引号转义，并在独立作用域中切换目录、通过 finally 恢复；切换失败立即停止。Unix 格式保留。两种格式均有固定期望值测试，每个平台还使用自身原生 shell 实际执行参数与目录恢复测试，覆盖空格、单引号、美元符号及方括号。未缩减平台矩阵、未删除整体测试或吞掉失败。

上述修复后的本地完整 go test ./...、go vet ./... 及定向登录/诊断测试通过。Windows 原生 shell 和平台脚本以第三轮准确提交的 Test 结果为准。
