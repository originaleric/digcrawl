## 中间问题与修复

### P1: Browser metadata 解码失败导致来源页 fallback 无法拿到 href/text

现象：

- 登录后浏览器可以打开头条作者页，但 `MetadataScript` 返回值在 Rod by-value 路径中被当成 `[]byte`/JSON 字符串处理，原逻辑继续走 `ObjectToJSON`，导致 metadata 为空。
- 结果是页面链接候选被丢弃，discover 误判失败。

修复：

- `internal/browser/browser_browse.go` 中 `evalPageMetadata` 优先解析 `RuntimeRemoteObject.Value`。
- 兼容 `map/object`、JSON string、`[]byte` 三类返回。
- metadata 执行失败时保留 `_metadata_error`，不再静默吞掉诊断信息。

### P2: 来源页 browser fallback 固定等待 `body`，对 SPA 页面过早

现象：

- 头条作者页是动态页面，等待 `body` 会过早提取，可能拿到空壳。

修复：

- `internal/source/service.go` 支持 source options 注入：
  - `wait_selector` / `browser_wait_selector`
  - `content_selector` / `browser_content_selector`
- 本轮临时头条来源配置使用 `wait_selector: "a[href]"`，等待页面实际出现链接后再提取。

## 残余风险

- 本轮使用的是临时测试配置中显式指定的 `chrome-headless-shell`；仓库 `config/config.yaml` 当前仍指向系统 Chrome 路径，若系统 Chrome 在 headless 下不稳定，生产配置应切回 headless shell 路径和对应 `ExtraArgs`。
- 头条作者页动态结构可能变化，建议长期保留 `wait_selector` 配置能力，并在生产 source 中为头条作者页配置 `wait_selector: "a[href]"`。
