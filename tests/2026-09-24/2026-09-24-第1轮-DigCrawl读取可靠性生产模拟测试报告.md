> 历史记录：本轮的控制端点/`TERM`→`KILL` 验证已被第 2 轮的直接进程组生命周期重构取代；请以同目录第 2 轮报告作为当前 Bridge 停止语义的验收依据。

- 日期：2026-09-24
- 范围：单机单 profile 的 Bridge 生命周期、浏览器连接恢复、直接读取 OCR 降级语义。
- 结论：源码层回归与静态检查通过；当前机器的最终真实 Toutiao MCP 调用被一个已进入 macOS 不可中断退出状态的旧 Bridge 阻断，不能把该现场误记为通过。

## 验收不变量

1. 已取得正文的读取不会因 OCR provider 失败变成顶层工具错误。
2. 一次 CDP/WebSocket 连接丢失只重放一次只读操作，且替代浏览器不能与旧 owner 并存。
3. Bridge 停止或重启是直接停启：无响应 owner 只能按精确 socket 参数终止；生命周期锁未释放时不启动替代实例。
4. 子进程已经写出启动失败状态时，调用者得到可操作诊断而不是笼统超时。

## 现场阻断与后续复测

新的 CLI 已安装。待操作系统回收旧 Bridge（必要时重启 macOS）后：

1. 启动同一 Skill profile 的 Bridge。
2. 用 `toutiao.article.read` 请求目标 URL，参数为 `format:["markdown"]`、`include_media:false`、`include_screenshot:false`。
3. 验收顶层 `status=success`、存在正文 Markdown；如 OCR provider 不可用，仅允许输出 `platform_metadata.ocr_status=degraded`，不允许返回 `TOOL_EXEC_FAILED`。
4. 检查同一 profile 仅有一个 Bridge owner 与一个浏览器进程树。
