## Findings

### P1: 新增国内渠道未进入 LocalBrowser 域名 allowlist，生产配置下无法采集

影响范围：

- B站
- 微博
- 快手
- 知乎

证据：

- 四个真实 URL 使用 `config/config.yaml` 均返回 `DOMAIN_NOT_ALLOWED`。
- `config/config.go` 默认 `LocalBrowser.AllowedDomains` 和 `config/config.yaml` 当前未包含这些平台域名。

风险：

- provider 代码即使已注册，用户按 README 或部署脚本运行时仍会被 gateway 拦截。
- watchlist 或手动 collect 都无法进入真实采集链路。

建议：

- 将新增平台域名补入默认配置和示例配置：
  - `bilibili.com`
  - `www.bilibili.com`
  - `m.bilibili.com`
  - `space.bilibili.com`
  - `b23.tv`
  - `weibo.com`
  - `www.weibo.com`
  - `m.weibo.cn`
  - `kuaishou.com`
  - `www.kuaishou.com`
  - `v.kuaishou.com`
  - `zhihu.com`
  - `www.zhihu.com`
  - `zhuanlan.zhihu.com`
- 补配置测试，避免 provider 注册后遗漏 gateway allowlist。

### P1: 微博反爬壳页被当作成功内容导出

证据：

- 临时放行后微博采集退出码为 0。
- 落盘文件为 `Sina Visitor System.json`。
- 输出字段：`title=Sina Visitor System`、`text_len=0`、`media_len=0`、`error_code=null`。

风险：

- 生产任务会把登录态失效、访客系统或反爬页误当成有效更新。
- watchlist 可能产生假更新、错误摘要或污染内容库。

建议：

- 微博 provider 在 browser 采集后增加反爬/登录壳页判定。
- 发现 `Sina Visitor System`、访客跳转、空正文且命中微博壳页时，应返回结构化错误，例如 `LOGIN_REQUIRED`、`CAPTCHA_REQUIRED` 或 `BOT_CHALLENGE`。
- 不应落盘为空正文的成功内容。

### P1: 快手真实视频页浏览器采集 90 秒超时

证据：

```text
[gateway-audit] tool=kuaishou.video.read ... status=error err_code=TOOL_EXEC_FAILED duration_ms=90001
collect: 找不到选择器 body: context deadline exceeded
```

风险：

- 快手真实 URL 在当前链路下不能形成稳定生产能力。
- 90 秒无有效进展会放大 watchlist 扫描耗时，并影响同批任务吞吐。

建议：

- 检查快手 provider 的页面加载策略和 selector 等待逻辑。
- 对页面不可达、挑战页、地域/登录限制做更早的错误分类。
- 增加短超时的 readiness probe，避免等待 `body` 一类基础 selector 到全局超时。

### P2: B站 API 输出内容过薄

证据：

- B站采集成功，但 `text_len=3`，正文只有 `www`。

风险：

- 对视频摘要和后续 agent summary 的输入不足。
- watchlist 能发现内容，但无法稳定生成可用摘要。

建议：

- 对 B站视频补充更完整的字段映射，例如简介、字幕、tag、UP 主、统计信息。
- 如果没有字幕，应明确标注 transcript unavailable，并根据视频链路接入 ASR/字幕总结流程。

## 结论

本轮 1-4 渠道生产级测试结论为 `FAILED/PARTIAL`：

- 构建和自动化回归通过。
- 正式配置下四个渠道均被 `DOMAIN_NOT_ALLOWED` 拦截，生产不可用。
- 临时放行后，B站和知乎可以采集落盘。
- 微博存在反爬页误判成功的问题。
- 快手真实页面采集超时。
- B站视频内容可采集但摘要输入不足。

下一轮修复应优先处理 P1：配置 allowlist、微博壳页错误分类、快手超时分类与采集稳定性。
