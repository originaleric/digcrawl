# 2026-08-17-第3轮-浏览器与ASR生产加固复验报告

## 1. 结论

- 结论：macOS 当前生产路径通过；Linux 配置渲染通过；Windows 实机运行待补充。
- 目标：关闭第 2 轮系统 review 中的跨平台 CDP、持久登录态、错误脱敏和本地 ASR 模型就绪风险。

## 2. 修复项

| 风险 | 修复 |
| --- | --- |
| Playwright 版本化缓存路径 | 浏览器自动发现系统 Chrome/Chromium，失效显式路径自动回退。 |
| Linux 含空格路径 | systemd unit 的 `ExecStart` 与 `Environment` 均使用 systemd 引号编码；日志改入 journald。 |
| Windows 含空格 profile 路径 | PowerShell 改为原生 `& $chrome @arguments` 调用，保留数组参数边界。 |
| 临时登录态 | 当前 Skill CookieStore 与 CDP profile 改至用户持久目录，并迁移既有 Cookie；目录权限为 `0700`。 |
| ASR 假就绪 | 新增 `ModelCacheDir`；doctor 在离线模式加载所选 Whisper 模型，模型不存在时明确失败且不触发下载。 |
| 浏览器错误泄露 | 客户端错误与结构化 details 删除 URL query/fragment，并限制原因文本长度。 |
| 页面关闭阻塞 | 页面关闭绑定有截止时间的 Rod context，不再为每次卡死 Close 遗留 goroutine。 |

## 4. 残余风险

1. Windows PowerShell 脚本已完成静态实现，但当前 macOS 主机没有 PowerShell/Windows Task Scheduler，尚未进行 Windows 实机启动验收。
2. 三个平台均使用当前用户的守护机制。macOS/Windows 需要用户登录；Linux 若要无人登录启动，需显式执行 `loginctl enable-linger <user>`。
3. CDP 仅绑定 `127.0.0.1`，但同机可访问该端口的本地进程仍可控制专用浏览器；不应在不受信任的多用户主机复用该 profile。
